# ШІ взаємодія 04 — Побудова Activity Diagram для UC-04

## Інструмент

Mermaid AI, Mermaid Live Editor.

## Оригінальний запит користувача

Створи Activity Diagram у Mermaid Flowchart для деталізації UC-04 Оформлення замовлення в моєму проєкті Онлайн-магазин друкованих книг. За основу візьми всі чотири сценарії SC-01–SC-04 із Завдання №3, функціональні вимоги FR-07–FR-15, ER-модель та Gherkin-сценарії. Залиши тих самих учасників: Customer, OrderUI, OrderService, StockService та Database. Хочу, щоб спочатку перевірялися контактні дані, потім паралельно наявність позицій та допустимість їхньої кількості через Fork/Join, а вже після цього — складські залишки з урахуванням групування однакових EDITION. Якщо всі перевірки пройдено успішно, потрібно розпочати транзакцію, повторно перевірити залишки, зафіксувати priceSnapshot, створити ORDER та ORDER_ITEM, розрахувати вартість позицій, оновити залишки та виконати commit(). У разі помилки передбач rollback(), а якщо причина в недостатній кількості примірників, потрібно додатково повідомити покупцеві актуальний залишок. Також покажи всі альтернативні сценарії, відповідні повідомлення про помилки, можливість виправлення даних, повторної спроби або припинення оформлення. Після успішного створення замовлення покупець має отримати підтвердження з підсумком замовлення. На діаграмі обов'язково покажи початок і завершення процесу, розгалуження if/else, Fork/Join, цикли, Send Signal та Accept Event. Для кращої читабельності використай різні кольори для учасників, умов та помилок. Назви операцій залиш англійською, а пояснення українською. Важливо, щоб діаграма відповідала моїй специфікації, чеклисту та матеріалам попередніх завдань. Надай готовий Mermaid-код для відображення в GitHub.

## Контекст звернення

Перед побудовою діаграми було підготовлено spec.md та CHECKLIST.md, визначено структуру Завдання №4 та обрано Activity Diagram у Mermaid Flowchart. Для забезпечення узгодженості діаграми я надала ШІ такі матеріали:

- ER-модель Завдання №1.
- Use Case Diagram Завдання №2.
- Функціональні вимоги EARS.
- Gherkin-сценарії UC04-S01–UC04-S04.
- Sequence Diagram SC-01–SC-04 Завдання №3.
- Матрицю трасування Завдання №3.
- Специфікацію та чеклист Завдання №4.

## Додаткові уточнення

Під час взаємодії з Mermaid AI виникла необхідність уточнити зміст функціональних вимог FR-07–FR-15, сценаріїв SC-01–SC-04, правила групування видань, повідомлення про помилки та організацію паралельних процесів. Було уточнено, що однакові EDITION групуються за editionId, паралельно виконуються лише дві перевірки всередині validateItems(), а кількість повторних спроб оформлення не обмежується. Для сценарію недопустимої кількості примірників прийнято припущення, що обов'язкові контактні дані вже заповнені.

## Результат звернення

Отримано Activity Diagram, яка об'єднує основний та альтернативні сценарії UC-04, відображає послідовність операцій, паралельні перевірки, транзакційне створення замовлення, обмін повідомленнями та обробку помилкових ситуацій. Під час перевірки графічного представлення було виявлено неповне відображення тексту всередині деяких блоків. Для усунення цього недоліку я додатково звернулася до ChatGPT.
