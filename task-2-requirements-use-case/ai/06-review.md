# Огляд 06 — Аналіз нефункціональних вимог NFR

## Пов'язаний промпт

`ai/06-prompt.md`

## Мета перевірки

Перевірити сім нефункціональних вимог онлайн-магазину друкованих книг, оцінити правильність їх оформлення у форматі EARS та визначити, чи достатньо конкретно описані показники й способи перевірки.

## Аналіз результату

У документі було описано сім нефункціональних вимог NFR-01–NFR-07. Вони охоплюють основні характеристики роботи книжкового магазину, зокрема швидкість відкриття каталогу, пошук книг, оформлення замовлення, доступність системи, безпеку передавання даних, адаптивність інтерфейсу та українську мову. Для швидкості роботи були встановлені межі у 2, 3 та 5 секунд. Також враховано навантаження до 100 одночасних користувачів, доступність системи 99,5%, використання HTTPS та підтримку екранів від 360 пікселів. Під час аналізу особливу увагу було приділено тому, чи можна перевірити кожну вимогу та чи правильно використано слова WHEN, WHILE і SHALL. Важливим моментом також було те, щоб вимоги не повторювали одна одну й не містили зайвих пояснень. Для вимог, пов'язаних зі швидкістю роботи, потрібно чітко зазначати умови навантаження. Для доступності та безпеки важливо залишити конкретні показники, а для адаптивності визначити розміри екранів, на яких проводитиметься перевірка.

## Оцінка результату

Підготовлені NFR охоплюють основні нефункціональні характеристики онлайн-магазину. Використання конкретних числових показників робить вимоги зрозумілішими та дозволяє визначити, як перевіряти їх виконання. Поділ на окремі вимоги з власними номерами та способами перевірки є зручним для читання. Такий формат також відповідає загальній структурі документації другого завдання. Водночас важливо стежити, щоб формулювання були короткими, а показники не суперечили одне одному.

## Прийняті рішення

Для документа вирішено залишити всі сім нефункціональних вимог, оскільки кожна з них описує окрему характеристику системи. Також залишено числові показники швидкості, доступності та навантаження. Вимоги оформлено окремими підзаголовками без таблиці, щоб документ було простіше читати. Основну структуру документа збережено. Особливу увагу приділено зрозумілості формулювань, використанню EARS та способам перевірки кожної вимоги.

## Статус

Сім нефункціональних вимог підготовлено для документації Завдання №2. Визначено основні критерії їх перевірки та моменти, на які потрібно звернути увагу під час остаточного перегляду.
