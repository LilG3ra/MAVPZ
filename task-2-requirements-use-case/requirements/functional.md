# Функціональні вимоги — EARS

**Проєкт:** Онлайн-магазин друкованих книг  
**Основа:** `spec.md`, UC-01–UC-05, Gherkin UC04-S01–UC04-S04 та ER-модель Завдання №1.

Кожна вимога має унікальний ідентифікатор. У записі EARS **WHEN** означає подію, **IF** — умову, **WHILE** — стан, а **SHALL** — обов'язкову спостережувану реакцію системи.

## Перелік функціональних вимог

| ID | Сценарій використання | Функціональна вимога (EARS) |
|---|---|---|
| FR-01 | UC-01 | WHEN покупець відкриває каталог, система SHALL відобразити перелік книг `BOOK` із назвами, авторами `AUTHOR` та основними жанрами `GENRE`. |
| FR-02 | UC-01 | IF каталог порожній, THEN система SHALL повідомити про відсутність книг. |
| FR-03 | UC-02 | WHEN покупець шукає книгу за назвою, система SHALL показати книги, назви яких відповідають запиту. |
| FR-04 | UC-02 | IF пошук не знайшов книг, THEN система SHALL показати повідомлення про відсутність результатів. |
| FR-05 | UC-03 | WHEN покупець відкриває інформацію про книгу, система SHALL відобразити її назву, автора, основний жанр та доступні видання `EDITION`. |
| FR-06 | UC-03 | WHEN покупець переглядає конкретне видання, система SHALL показати ISBN, видавництво `PUBLISHER`, рік публікації, ціну та доступну кількість примірників. |
| FR-07 | UC-04 | WHILE покупець оформлює замовлення як гість, система SHALL дозволяти продовжити оформлення без реєстрації. |
| FR-08 | UC-04 | IF покупець підтверджує замовлення без позицій, THEN система SHALL відхилити оформлення без створення `ORDER`. |
| FR-09 | UC-04 | IF покупець указав кількість примірників меншу за 1, THEN система SHALL відхилити оформлення, повідомити про мінімальну кількість 1 і не створювати `ORDER`. |
| FR-10 | UC-04 | WHEN покупець підтверджує замовлення, система SHALL перевірити доступний залишок кожного обраного видання `EDITION`. |
| FR-11 | UC-04 | IF замовлена кількість перевищує залишок хоча б одного видання, THEN система SHALL повідомити доступну кількість та не створювати `ORDER`. |
| FR-12 | UC-04 | IF покупець не заповнив обов'язкові контактні дані, THEN система SHALL повідомити про необхідність їх заповнення та не створювати `ORDER`. |
| FR-13 | UC-04 | WHEN покупець підтверджує замовлення зі щонайменше однією позицією, заповненими контактними даними, допустимою кількістю та достатніми залишками, система SHALL створити один `ORDER` з відповідними `ORDER_ITEM`, прив'язаними до конкретних `EDITION`. |
| FR-14 | UC-04 | WHEN система створює `ORDER_ITEM`, система SHALL зафіксувати кількість та ціну одиниці видання на момент оформлення й відобразити суму позиції як добуток кількості та зафіксованої ціни. |
| FR-15 | UC-04 | WHEN замовлення успішно створено, система SHALL показати покупцеві підтвердження оформлення. |
| FR-16 | UC-05 | WHEN працівник магазину відкриває перелік замовлень, система SHALL відобразити замовлення та їхні позиції. |
| FR-17 | UC-05 | WHEN працівник вибирає наявне замовлення і встановлює статус «Опрацьовано», система SHALL зберегти оновлений статус. |
| FR-18 | UC-05 | IF працівник намагається відкрити неіснуюче замовлення, THEN система SHALL повідомити, що замовлення не знайдено. |
