# Завдання №2 — Вимоги та Use Cases (UC + Gherkin + EARS + NFR)

**Дисципліна:** Компоненти програмної інженерії.

**Тема проєкту:** Інформаційна система онлайн-магазину друкованих книг.

## Опис проєкту

Проєкт продовжує Завдання №1 і присвячений опису взаємодії користувачів з онлайн-магазином друкованих книг. Покупець може переглядати каталог, шукати книги, отримувати інформацію про книги та видання й оформлювати замовлення без обов'язкової реєстрації. Працівник магазину переглядає та опрацьовує оформлені замовлення.

## Мета завдання

Визначити акторів системи й побудувати Use Case-діаграму, описати сценарії використання мовою Gherkin, сформулювати функціональні вимоги у форматі EARS, нефункціональні вимоги (NFR) та матрицю трасування.

## Основні актори та Use Cases

1. **Покупець** — переглядає каталог, шукає книги, отримує інформацію про книги та видання й оформлює замовлення (UC-01–UC-04).
2. **Працівник магазину** — переглядає та опрацьовує замовлення (UC-05).

## Основні бізнес-правила

- Замовлення можна оформити без реєстрації.
- Замовлення має містити одну або декілька позицій.
- Кількість замовлених примірників має бути додатною та не перевищувати доступні залишки.
- Кожна позиція замовлення пов'язана з конкретним виданням книги відповідно до ER-моделі Завдання №1.
- Ціну видання на момент підтвердження замовлення потрібно зафіксувати в позиції замовлення.
- Перед створенням замовлення система перевіряє обов'язкові контактні дані покупця.
- Працівник магазину може змінити статус замовлення на «Опрацьовано».

## Інструменти

- Mermaid — побудова Use Case-діаграми.
- Gherkin — опис сценаріїв використання у форматі Given / When / Then.
- EARS — формулювання функціональних вимог.
- GitHub — зберігання файлів та історії змін.
- ChatGPT — допоміжний інструмент для аналізу, пояснень і перевірки.

## Перевірка Use Case-діаграми

Для відтворення Use Case-діаграми:

1. Відкрити файл `diagrams/UC.mmd`.
2. Скопіювати його вміст.
3. Перейти до редактора [Mermaid Live](https://mermaid.live/).
4. Вставити код у редактор.
5. Перевірити, що діаграма відображається без помилок.

Готове графічне представлення збережено у файлі `diagrams/Use-cases.png`.

## Межі роботи

У межах завдання не реалізуються вебзастосунок, фізична база даних, онлайн-оплата, інтеграція з поштовими службами та повна система авторизації. Створюються моделі, сценарії й документація вимог. Нефункціональні показники визначено як цільові значення, а не як результати тестування готового продукту.
