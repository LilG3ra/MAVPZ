# Завдання №2 — Вимоги та Use Cases (UC + Gherkin + EARS + NFR)

**Дисципліна:** Компоненти програмної інженерії.

**Тема проєкту:** Інформаційна система онлайн-магазину друкованих книг.

## Опис проєкту

Проєкт продовжує Завдання №1 і присвячений опису взаємодії користувачів з онлайн-магазином друкованих книг. Покупець може переглядати каталог та інформацію про книги й видання, оформлювати замовлення як гість без реєстрації та оплачувати його. Працівник магазину організовує доставку оплаченого замовлення. Для оплати передбачено взаємодію із зовнішнім платіжним сервісом.

## Мета завдання

Визначити акторів системи й побудувати Use Case-діаграму, описати сценарії використання мовою Gherkin, сформулювати функціональні вимоги у форматі EARS, нефункціональні вимоги (NFR) та матрицю трасування.

## Основні актори та Use Cases

1. **Покупець** — переглядає каталог, отримує інформацію про книги, оформлює та оплачує замовлення.
2. **Працівник магазину** — організовує доставку замовлень.
3. **Платіжний сервіс** — зовнішня система, яка обробляє оплату та передає її результат.

## Основні бізнес-правила

- Замовлення можна оформити без реєстрації.
- Замовлення має містити одну або декілька позицій.
- Кількість замовлених примірників має бути додатною та не перевищувати доступні залишки.
- Кожна позиція замовлення пов'язана з конкретним виданням книги відповідно до ER-моделі Завдання №1.
- Ціну видання на момент підтвердження замовлення потрібно зафіксувати в позиції замовлення.
- Оплата здійснюється після створення замовлення через зовнішній платіжний сервіс (припущення, що потребує підтвердження).
- Доставку можна оформити після успішної оплати; для одного замовлення передбачена не більш ніж одна доставка.

## Інструменти

- Mermaid — побудова Use Case-діаграми.
- Gherkin — опис сценаріїв використання у форматі Given / When / Then.
- EARS — формулювання функціональних вимог.
- GitHub — зберігання файлів та історії змін.
- ChatGPT — допоміжний інструмент для аналізу, пояснень і перевірки.

## Документація

- `spec.md` — специфікація та критерії прийняття.
- `use-cases.md` — опис акторів і сценаріїв використання.
- `diagrams/use-cases.puml` — вихідний код Use Case-діаграми.
- `diagrams/use-cases.png` — графічне представлення діаграми.
- `scenarios/uc-03-place-order.feature` — Gherkin-сценарії складного UC-03.
- `requirements/functional.md` — функціональні вимоги EARS.
- `requirements/nonfunctional.md` — нефункціональні вимоги NFR.
- `traceability.md` — матриця трасування вимог і Use Cases.
- `adr/` — обґрунтування ключових рішень.
- `ai/` — історія взаємодії з ШІ та матеріали для рев'ю.
- `ASSUMPTIONS.md` — припущення, що потребують підтвердження.
- `CHECKLIST.md` — чекліст «Готово».
- `DEFENSE.md` — підсумковий захист лабораторної роботи.

## Перевірка Use Case-діаграми

Для відтворення Use Case-діаграми:

1. Відкрити файл `diagrams/use-cases.puml`.
2. Скопіювати його вміст.
3. Перейти до редактора [https://mermaid.live/](https://mermaid.live/).
4. Вставити код у редактор.
5. Перевірити, що діаграма відображається без помилок. Готове графічне представлення збережено у файлі `diagrams/use-cases.png`.

## Межі роботи
